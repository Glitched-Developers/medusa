# API бэкенда «Медузки»

Сейчас приложение всё делает само: парсит HTML сайта БелГУ, хранит значки в коде,
а обращения — на телефоне. Этот документ — контракт сервера, который снимает
хрупкость парсинга и даёт обновлять значки, мат-лист и новости без пересборки APK.

Клиент уже умеет работать офлайн: любой ответ кешируется, при недоступности API
используется последний успешный снимок. Поэтому сервер можно поднимать постепенно,
эндпоинт за эндпоинтом.

## Общие правила

- База: `https://api.meduzka.ru/v1` (адрес уточняется при деплое).
- Формат: JSON UTF-8, `Content-Type: application/json`.
- Авторизации нет: только публичные данные расписания.
- Кеширование: `ETag` + `If-None-Match`, `Cache-Control: public, max-age=…`.
- Ошибки: `{"error": {"code": "not_found", "message": "Группа не найдена"}}`,
  HTTP 4xx/5xx.
- Время: ISO 8601 UTC (`2026-11-17T09:30:00Z`).
- Версия в пути (`/v1`). Ломающие изменения — только в `/v2`.

Общая обёртка ответа с данными:

```json
{
  "data": { },
  "updatedAt": "2026-11-17T09:30:00Z",
  "source": "bsuedu"
}
```

`updatedAt` — когда данные реально обновились на сайте (не когда отдан кеш).

## 1. Расписание группы

`GET /v1/schedule/group/{group}?week=this|next|last`

Заменяет `BelguScheduleParser` в приложении. Формат — ровно тот, что уже
разбирает `ScheduleResponse.fromJson`, чтобы клиент не менялся.

```json
{
  "data": {
    "group": 12002301,
    "week": "this",
    "schedule": {
      "12.10.2026 Понедельник": [
        {
          "number": 1,
          "time": "8:30 - 10:05",
          "type": "лаб.",
          "name": "CASE-средства проектирования информационных систем",
          "teacher": "Золотарева И. А.",
          "teacherId": 107180,
          "auditory": "6-12",
          "auditoryId": 7236,
          "online": false,
          "subgroup": 1,
          "key": "1|лаб.|CASE-средства…",
          "url": "https://pegasus.bsuedu.ru/…"
        }
      ]
    }
  },
  "updatedAt": "2026-11-17T06:12:00Z",
  "source": "bsuedu"
}
```

Правила:

- `teacherId` и `auditoryId` — из ссылок сайта (`?teacher=`, `?auditory=`),
  чтобы клиент открывал расписание преподавателя/кабинета без поиска.
- Ключи дней — как на сайте («12.10.2026 Понедельник»).
- Пустая неделя — `"schedule": {}`, не 404.
- 404 — только если группы нет в вузе.

TTL: 15 минут в течение учебного дня, 6 часов ночью и в выходные.
`ETag` обязателен: клиент шлёт `If-None-Match` и получает `304`.

## 2. Расписание преподавателя и аудитории

`GET /v1/schedule/teacher/{teacherId}?week=…`
`GET /v1/schedule/auditorium/{auditoriumId}?week=…`

Тело — та же структура, что у группы, но `data` содержит
`teacher`/`auditorium` вместо `group`, а `schedule` — пары с полем `group`
(для преподавателя) или `teacher` (для аудитории).

## 3. Справочники

`GET /v1/auditoriums` — полный список кабинетов (сейчас клиент скачивает
его сам раз в неделю):

```json
{ "data": [ { "id": 7236, "name": "6-12", "building": "Учебный корпус №15" } ] }
```

TTL: 7 дней, `ETag`.

`GET /v1/teachers/search?q=золот` — подсказки поиска:

```json
{ "data": [ { "id": 107180, "name": "Золотарева И. А." } ] }
```

Не больше 20 результатов, регистр и лишние пробелы нормализуются на сервере.

`GET /v1/groups/search?q=1200` — то же для групп.

## 4. Каталог значков

`GET /v1/badges`

Сейчас значки — константы в `BadgeCatalog`. С сервером новый значок появляется
без обновления приложения.

```json
{
  "data": [
    {
      "id": "first_step",
      "title": "Первый шаг",
      "description": "Заполнил профиль",
      "icon": "person_outline",
      "tier": "common",
      "points": 5,
      "secret": false,
      "code": null
    },
    {
      "id": "medusa_gold",
      "title": "Золотая медуза",
      "description": "Эксклюзивный значок",
      "icon": "auto_awesome",
      "tier": "exclusive",
      "points": 0,
      "secret": true,
      "code": "MEDUZA-2026"
    }
  ]
}
```

- `icon` — имя Material-иконки; неизвестную клиент заменяет на `emoji_events`.
- `code` — для эксклюзивных, `null` у обычных.
- Условия выдачи (профиль, избранное, помощь) остаются на клиенте: сервер
  отдаёт только каталог, а не прогресс пользователя.
- Кеш: 24 часа, `ETag`. При ошибке — встроенный каталог из APK.

TTL: 24 часа; при `304` — продлить локальный кеш.

## 5. Мат-лист

`GET /v1/profanity`

```json
{ "data": { "roots": ["хуй", "пизд", "бля"], "words": ["лох", "гад"] } }
```

- `roots` — ищутся как часть слова (ловятся производные).
- `words` — сверяются целиком (чтобы не ругаться на «лохматый»).
- Кеш: 24 часа. При ошибке — список, вшитый в APK.

## 6. Новости

`GET /v1/news?limit=20&cursor=…`

Сейчас клиент парсит HTML ленты БелГУ. Сервер отдаёт уже готовые статьи:

```json
{
  "data": {
    "items": [
      {
        "id": "news-2026-11-17-1",
        "title": "…",
        "summary": "…",
        "body": "…",
        "imageUrl": "https://…",
        "publishedAt": "2026-11-17T08:00:00Z",
        "url": "https://bsuedu.ru/…"
      }
    ],
    "nextCursor": "2026-11-10T00:00:00Z"
  }
}
```

TTL: 10 минут. Клиент показывает кеш и обновляет ленту в фоне.

## 7. Обращения (баг-репорты)

Сервер не обязателен: в приложении есть кнопка «Открыть issue на GitHub» —
она формирует предзаполненный issue в репозитории `Glitched-Developers/medusa`.
Скриншот пользователь прикрепляет к issue вручную (GitHub не принимает файлы
через URL).

Если появится свой трекер:

`POST /v1/reports` (multipart/form-data)

| Поле | Тип | Описание |
|---|---|---|
| `kind` | `bug` / `feature` | тип обращения |
| `text` | string | описание, 10–4000 символов |
| `screenshot` | file, необязательно | PNG/JPEG до 8 МБ |
| `device` | JSON-строка | модель, Android, сборка, экран |

Ответ `201`:

```json
{ "id": "rep_01J…", "url": "https://github.com/Glitched-Developers/medusa/issues/42" }
```

Rate limit: 5 обращений в час с одного IP, `429` с `Retry-After`.

## 8. Что остаётся на клиенте

- Офлайн-кеш расписания и настройка срока хранения.
- Подсчёт очков и уровней (каталог значков — с сервера, условия — локально).
- Уведомления, напоминания, избранное, чаты.
- Эксклюзивные значки: код проверяется на сервере, но и локально кешируется,
  чтобы уже выданный значок не пропадал без сети.

## 9. Порядок внедрения

1. `/v1/schedule/*` — самое хрупкое место (CSS-селекторы сайта).
2. `/v1/auditoriums` и `/v1/teachers/search` — снимают лишние запросы к сайту.
3. `/v1/badges` — новые значки без релиза.
4. `/v1/profanity` — обновление списка без релиза.
5. `/v1/news` — когда лента на сайте станет нестабильной.
6. `/v1/reports` — только если GitHub Issues станет неудобно.
